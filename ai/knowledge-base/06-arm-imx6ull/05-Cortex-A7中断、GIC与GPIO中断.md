### 一、今天的主要学习内容

今天主要学习 ARM Cortex-A7 的中断系统，以及 i.MX6ULL 中 GPIO 中断的实现过程。

主要内容：

1. ARM 中断的基本处理流程；
2. Cortex-A7 的 GIC；
3. GPIO 中断产生过程；
4. GPIO 中断寄存器；
5. CP15 协处理器；
6. VBAR 异常向量表基地址；

9. GPIO 中断模块化设计；
10. 通过回调函数降低程序耦合性。

## 二、什么是中断

中断是处理器在执行当前程序的过程中，由某个外部或内部事件产生请求，使 CPU 暂停当前程序，转而处理相应事件的一种机制。

例如：

```
按键按下
   ↓
GPIO检测到电平变化
   ↓
产生GPIO中断
   ↓
GIC接收到中断请求
   ↓
CPU进入IRQ异常
   ↓
执行中断服务函数
   ↓
处理按键
   ↓
恢复原来的程序
```

因此，中断可以让 CPU 不需要一直查询硬件状态。

---

## 三、GPIO中断的基本结构

i.MX6ULL 中，GPIO 可以作为中断源。

基本结构：

```
GPIO中断源
    ↓
GIC
    ↓
CPU
    ↓
IRQ异常
    ↓
IRQ异常处理函数
    ↓
具体中断服务函数
```

图中的 GPIO 中断源最终连接到 GIC，再由 GIC 向处理器发送 IRQ 请求。

---

## 四、GPIO按键电路

今天分析了 GPIO 按键产生中断的硬件电路。

按键一端连接：

```
GND
```

另一端连接：

```
GPIO1_IO18
```

同时通过：

```
10KΩ
```

电阻连接到：

```
DCDC3V3
```

因此按键没有按下时：

```
GPIO1_IO18 ≈ 3.3V
```

按键按下后：

```
GPIO1_IO18 → GND
```

GPIO 电平发生变化，从而可以触发 GPIO 中断。

可以理解为：

```
未按下：

3.3V
 │
10K
 │
GPIO1_IO18
 │
开关断开
 │
GND

按下：

3.3V
 │
10K
 │
GPIO1_IO18
 │
开关
 │
GND
```

这种电路属于典型的**上拉输入按键电路**。

---

## 五、GPIO中断的产生

GPIO 输入电平发生变化后，GPIO 内部检测到对应的中断条件。

整个过程：

```
按键动作
   ↓
GPIO1_IO18电平变化
   ↓
GPIO中断检测
   ↓
GPIO产生中断请求
   ↓
GIC接收中断
   ↓
GIC向CPU发送IRQ
   ↓
CPU进入IRQ异常
```

所以 GPIO 本身负责产生中断请求，而 GIC 负责对中断请求进行管理和分发。

---

## 六、GIC

GIC：

> Generic Interrupt Controller，通用中断控制器。

它是 ARM 系统中的重要中断控制模块。

主要作用是：

```
接收中断请求
      ↓
判断中断是否使能
      ↓
判断中断优先级
      ↓
将中断发送给对应CPU
```

因此：

```
GPIO
 ↓
产生中断
 ↓
GIC
 ↓
管理和分发
 ↓
CPU
```

---

## 七、GIC的主要作用

GIC主要完成以下工作：

#### 1. 接收中断请求

GPIO、UART、Timer 等外设都可以产生中断。

例如：

```
GPIO
UART
PWM
TIMER
...
 ↓
GIC
```

---

#### 2. 中断使能

只有打开相应中断后，中断请求才能正常进入处理流程。

---

#### 3. 中断优先级管理

当多个中断同时发生时，GIC 可以根据优先级确定先处理哪个中断。

---

#### 4. 中断分发

GIC 根据系统配置将中断请求发送给相应的处理器。

在单核 Cortex-A7 系统中，可以理解为：

```
GIC
 ↓
CPU
```

---

## 八、ARM异常与IRQ

当 IRQ 中断产生后，CPU 会进入：

```
IRQ模式
```

也就是 ARM 的一种异常处理模式。

ARM 异常处理的一般流程：

```
① 中断源产生中断请求
        ↓
② CPU判断是否响应中断
        ↓
③ 检查中断屏蔽状态
        ↓
④ 保存当前程序状态
        ↓
⑤ 保存返回地址
        ↓
⑥ 跳转到异常向量
        ↓
⑦ 执行IRQ处理程序
        ↓
⑧ 恢复现场
        ↓
⑨ 返回原程序继续执行
```

---

## 九、IRQ异常处理流程

今天重点学习了 IRQ 的处理过程。

可以总结为：

```
中断源发生
    ↓
CPU收到IRQ
    ↓
保护现场
    ↓
执行中断服务程序
    ↓
恢复现场
    ↓
返回原程序
```

其中“保护现场”和“恢复现场”非常重要。

因为 CPU 在处理中断之前，正在执行原来的程序。

如果不保存原程序运行状态，中断处理结束之后就无法正确继续原来的程序。

---

## 十、异常向量表

ARM 发生异常后，需要根据异常类型找到对应的处理入口。

因此 ARM 需要使用：

```
异常向量表
```

经典 ARM 异常向量表包括：

```
0x00  Reset
0x04  Undefined Instruction
0x08  Software Interrupt
0x0C  Prefetch Abort
0x10  Data Abort
0x14  Reserved
0x18  IRQ
0x1C  FIQ
```

其中：

```
IRQ → 0x18
```

所以当 CPU 发生 IRQ 异常时，需要从 IRQ 对应的异常向量进入 IRQ 处理流程。

---

## 十一、CP15协处理器

今天还学习了：

```
CP15
```

CP15 是 ARM Cortex-A 系列中用于系统控制的一组协处理器寄存器。

主要用于：

```
系统控制
Cache控制
MMU控制
异常向量基地址配置
内存系统配置
```

因此在 ARM 裸机开发中，经常需要使用 CP15。

---

## 十二、CPSR和SPSR

ARM 处理器中有：

```
CPSR
SPSR
```

#### CPSR

CPSR：

> Current Program Status Register

即当前程序状态寄存器。

主要保存：

```
条件标志
CPU工作状态
处理器模式
中断屏蔽状态
```

---

#### SPSR

SPSR：

> Saved Program Status Register

即保存程序状态寄存器。

发生异常时，当前 CPSR 中的重要状态会保存到对应异常模式的 SPSR 中。

因此可以理解为：

```
正常运行
CPSR
 ↓
发生异常
 ↓
保存到SPSR
```

异常处理结束后，再恢复原来的程序状态。

---

## 十三、VBAR异常向量基地址

Cortex-A7 中可以通过 CP15 设置异常向量表基地址。

VBAR：

> Vector Base Address Register

即异常向量表基地址寄存器。

例如：

```
mcr p15, 0, r0, c12, c0, 0
```

用于设置 VBAR。

如果：

```
r0 = 0x87800000
```

那么：

```
VBAR = 0x87800000
```

异常向量表就从该地址开始。

因此：

```
0x87800000
    ↓
异常向量表基地址
    ↓
Reset
Undefined
SVC
Abort
IRQ
FIQ
```

---

## 十四、打开ICache

今天的代码中还出现了：

```
orr r0, r0, #(1 << 12)
```

然后：

```
mcr p15, 0, r0, c1, c0, 0
```

这里涉及 CP15 的系统控制寄存器。

其中：

```
bit 12
```

与 ICache 的使能有关。

因此可以通过修改 CP15 系统控制寄存器来打开 ICache。

---

## 十五、IRQ异常处理代码

IRQ异常向量通常位于：

```
0x18
```

异常向量中可以跳转到真正的 IRQ 处理程序。

例如：

```
sub lr, lr, #4
stmfd sp!, {r0-r12, lr}
```

这里首先对 LR 进行调整，然后将寄存器保存到栈中。

---

## 十六、为什么需要保存寄存器

进入 IRQ 后，CPU 原来正在执行某个程序。

假设原程序正在使用：

```
r0
r1
r2
...
r12
```

如果 IRQ 处理函数直接修改这些寄存器，那么返回原程序后可能导致原来的数据发生错误。

所以进入 IRQ 后需要：

```
保存寄存器
   ↓
处理中断
   ↓
恢复寄存器
   ↓
返回原程序
```

例如：

```
stmfd sp!, {r0-r12, lr}
```

就是将寄存器保存到栈中。

---

## 十七、切换处理器模式

IRQ处理过程中需要进行模式切换。

例如：

```
cps #0x1F
```

表示切换到：

```
System模式
```

然后：

```
cps #0x12
```

表示切换到：

```
IRQ模式
```

不同模式具有不同的用途。

IRQ模式主要用于：

```
处理中断
```

System模式可以使用与 User 模式相同的寄存器组织，但具有特权级。

---

## 十八、GIC中断初始化流程

今天图中给出了 GIC 初始化过程。

主要步骤：

#### 第一步：设置GIC中断优先级

例如：

```
GIC_SetPriority(99, 0);
```

用于设置指定中断的优先级。

---

#### 第二步：设置中断使能

例如：

```
GIC_EnableIRQ(99);
```

打开对应的中断。

---

#### 第三步：获取GIC基地址

通过 CP15：

```
mrc p15, 4, r0, c15, c0, 0
```

获取 GIC 相关基地址。

然后：

```
add r0, r0, #0x2000
```

得到相应 GIC 地址。

---

## 十九、GIC寄存器

GIC 中存在多个重要寄存器。

例如：

```
GIC Distributor
GIC CPU Interface
```

Distributor 主要负责：

```
中断分发
中断使能
优先级
中断目标CPU
```

CPU Interface 负责：

```
CPU与GIC之间的中断接口
```

因此可以理解为：

```
GPIO
 ↓
GIC Distributor
 ↓
GIC CPU Interface
 ↓
CPU
```

---

## 二十、GPIO中断寄存器

GPIO 中断主要涉及以下寄存器。

### 1. 中断配置寄存器

例如：

```
GPIO1->ICR2
```

用于设置 GPIO1 对应引脚的中断触发方式。

例如：

```
GPIO1->ICR2 |= (3 << 4);
```

用于配置相应引脚的中断触发条件。

---

## 二十一、GPIO中断屏蔽寄存器

例如：

```
GPIO1->IMR
```

即：

> Interrupt Mask Register

中断屏蔽寄存器。

例如：

```
GPIO1->IMR |= (1 << 18);
```

用于打开：

```
GPIO1_IO18
```

对应的中断。

可以理解为：

```
IMR
 ↓
决定GPIO中断是否允许进入中断处理流程
```

---

## 二十二、GPIO中断状态寄存器

例如：

```
GPIO1->ISR
```

即：

> Interrupt Status Register

用于查看 GPIO 中断状态。

例如：

```
if ((GPIO1->ISR & (1 << 18)) != 0)
{
    ...
}
```

表示检查：

```
GPIO1_IO18
```

对应的中断状态。

---

## 二十三、清除GPIO中断状态

GPIO 中断处理完成后，需要清除中断状态。

例如：

```
GPIO1->ISR |= (1 << 18);
```

完成中断标志清除。

因此 GPIO 中断处理通常是：

```
检查ISR
   ↓
确认GPIO1_IO18发生中断
   ↓
执行相应操作
   ↓
清除ISR
```

如果不及时清除中断状态，可能导致中断重复进入。

---

## 二十四、GPIO中断完整流程

今天最重要的一条流程：

```
按键按下
   ↓
GPIO1_IO18电平变化
   ↓
GPIO检测到中断条件
   ↓
GPIO1->ISR产生状态
   ↓
GPIO中断请求
   ↓
GIC
   ↓
CPU IRQ
   ↓
异常向量0x18
   ↓
IRQ_Handler
   ↓
中断服务函数
   ↓
判断GPIO1_IO18
   ↓
LED动作
   ↓
清除GPIO1->ISR
   ↓
恢复现场
   ↓
返回原程序
```

## 二十五、中断服务函数

中断服务函数用于真正处理发生的中断。

例如：

```c
void system_interrupt_handler(IRQn_Type irq)
{
    if (irq == GPIO1_Combined_16_31_IRQn)
    {
        if ((GPIO1->ISR & (1 << 18)) != 0)
        {
            /* 点灯 */
            GPIO1->ISR |= (1 << 18);
        }
    }
}
```

这里首先判断：

```
是不是GPIO1的中断
```

然后判断：

```
是不是GPIO1_IO18产生的中断
```

如果确定是：

```
执行LED控制
清除中断状态
```

---

## 二十六、为什么要判断中断号

一个 GPIO 模块可以有多个 GPIO 引脚。

例如：

```
GPIO1_IO16
GPIO1_IO17
GPIO1_IO18
GPIO1_IO19
...
```

因此进入 GPIO 中断处理函数后，还需要进一步判断：

```
到底是哪一个GPIO产生了中断？
```

所以采用：

```
if (irq == GPIO1_Combined_16_31_IRQn)
```

先判断 GPIO 中断组，再检查：

```
GPIO1->ISR & (1 << 18)
```

判断具体的 GPIO1_IO18。

---

## 二十七、中断处理函数的整体结构

```
IRQ异常
  ↓
system_interrupt_handler()
  ↓
判断中断号
  ↓
判断具体GPIO
  ↓
处理中断
  ↓
清除中断标志
  ↓
返回
```
