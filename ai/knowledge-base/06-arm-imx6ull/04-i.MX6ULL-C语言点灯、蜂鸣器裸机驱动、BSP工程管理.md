## 二、使用C语言实现LED点灯

之前使用 ARM 汇编完成了 LED 点灯，今天将 LED 点灯程序改成 C 语言实现。

C 语言点灯的核心思想没有改变，仍然需要完成：

```
时钟初始化
    ↓
IOMUXC引脚复用
    ↓
引脚电气属性配置
    ↓
GPIO方向配置
    ↓
GPIO数据控制
    ↓
LED亮灭
```

C 语言主要是将对寄存器的操作封装成函数，使程序更加容易理解和维护。

## 三、volatile关键字

在裸机开发中，经常需要直接访问硬件寄存器。

例如：

```
#define P2 *((volatile unsigned char *)0x80)
```

这里使用了：

```
volatile
```

`volatile` 的作用是告诉编译器：

> 这个变量的值可能在程序代码之外发生变化，每次访问都需要真正从指定地址读取或写入，不能随意进行优化。

硬件寄存器就是典型的 `volatile` 使用场景。

因此：

```
volatile unsigned int
```

通常用于：

```
硬件寄存器
共享数据
可能被中断修改的数据
```

在 SOC 裸机开发中，访问 GPIO、时钟控制器等硬件寄存器时尤其重要。

---

## 四、C语言直接定义寄存器地址

C 语言可以通过指针直接访问指定的内存地址。

例如：

```
#define CCM_CCGR0 *((unsigned int *)0x020C4068)
```

可以理解为：

```
0x020C4068
     ↓
转换成unsigned int指针
     ↓
访问这个地址中的32位数据
     ↓
通过CCM_CCGR0进行操作
```

这样就可以像操作普通变量一样操作硬件寄存器：

```
CCM_CCGR0 = 0xFFFFFFFF;
```

本质上是向：

```
0x020C4068
```

这个硬件地址写入：

```
0xFFFFFFFF
```

## 五、i.MX6ULL时钟控制寄存器

今天使用了 CCM 模块的多个时钟控制寄存器：

```
#define CCM_CCGR0 *((unsigned int *)0x020C4068)
#define CCM_CCGR1 *((unsigned int *)0x020C406C)
#define CCM_CCGR2 *((unsigned int *)0x020C4070)
#define CCM_CCGR3 *((unsigned int *)0x020C4074)
#define CCM_CCGR4 *((unsigned int *)0x020C4078)
#define CCM_CCGR5 *((unsigned int *)0x020C407C)
#define CCM_CCGR6 *((unsigned int *)0x020C4080)
```

通过 `clock_init()` 进行初始化：

```c
void clock_init(void)
{
    CCM_CCGR0 = 0xFFFFFFFF;
    CCM_CCGR1 = 0xFFFFFFFF;
    CCM_CCGR2 = 0xFFFFFFFF;
    CCM_CCGR3 = 0xFFFFFFFF;
    CCM_CCGR4 = 0xFFFFFFFF;
    CCM_CCGR5 = 0xFFFFFFFF;
    CCM_CCGR6 = 0xFFFFFFFF;
}
```

这里将相关时钟控制寄存器设置为：

```
0xFFFFFFFF
```

为后续外设操作提供时钟。

## 六、GPIO相关寄存器

今天使用 GPIO1_IO03 控制 LED。

定义相关寄存器：

```
#define IOMUXC_SW_MUX_CTL_PAD_GPIO1_IO03 \
    *((unsigned int *)0x020E0068)

#define IOMUXC_SW_PAD_CTL_PAD_GPIO1_IO03 \
    *((unsigned int *)0x020E02F4)

#define GPIO1_DR \
    *((unsigned int *)0x0209C000)

#define GPIO1_GDIR \
    *((unsigned int *)0x0209C004)
```

主要分为：

| 寄存器 | 作用 |
| --- | --- |
| IOMUXC_SW_MUX_CTL_PAD_GPIO1_IO03 | GPIO引脚复用 |
| IOMUXC_SW_PAD_CTL_PAD_GPIO1_IO03 | GPIO引脚电气属性 |
| GPIO1_GDIR | GPIO输入输出方向 |
| GPIO1_DR | GPIO数据寄存器 |

因此：

```
IOMUXC
 ↓
确定引脚使用什么功能
 ↓
GDIR
 ↓
确定输入还是输出
 ↓
DR
 ↓
控制GPIO电平
```

## 七、LED初始化

LED 初始化函数：

```c
void led_init(void)
{
    IOMUXC_SW_MUX_CTL_PAD_GPIO1_IO03 = 0x05;
    IOMUXC_SW_PAD_CTL_PAD_GPIO1_IO03 = 0x10B0;
    GPIO1_GDIR |= (1 << 3);
}
```

分为三个步骤。

#### 1. 设置复用功能

```
IOMUXC_SW_MUX_CTL_PAD_GPIO1_IO03 = 0x05;
```

将对应引脚设置为 GPIO 功能。

#### 2. 设置电气属性

```
IOMUXC_SW_PAD_CTL_PAD_GPIO1_IO03 = 0x10B0;
```

配置 GPIO 引脚的电气特性。

#### 3. 设置GPIO方向

```
GPIO1_GDIR |= (1 << 3);
```

将 GPIO1 的第3位设置为1，使：

```
GPIO1_IO03 → 输出
```

---

## 八、LED点亮与熄灭

LED 的控制通过 `GPIO1_DR` 数据寄存器完成。

### 1. LED点亮

```c
void led_on(void)
{
    GPIO1_DR &= ~(1 << 3);
}
```

这里：

```
1 << 3
```

表示：

```
0000 0000 0000 1000
```

然后：

```
~(1 << 3)
```

将第3位变成0。

最后：

```
GPIO1_DR &= ~(1 << 3);
```

将 GPIO1_IO03 输出低电平，从而点亮 LED。

---

### 2. LED熄灭

```c
void led_off(void)
{
    GPIO1_DR |= (1 << 3);
}
```

通过：

```
1 << 3
```

得到第3位为1的数。

使用按位或：

```
GPIO1_DR |= (1 << 3);
```

将 GPIO1_IO03 设置为高电平，使 LED 熄灭。

---

## 九、LED闪烁

除了点亮和熄灭，还可以通过异或操作实现 LED 翻转。

例如：

```c
void led_flicker(void)
{
    GPIO1_DR ^= (1 << 3);
}
```

`^` 是按位异或。

异或的特点：

```
原来为0 → 变成1
原来为1 → 变成0
```

因此：

```
GPIO1_IO03
    ↓
每执行一次
    ↓
电平翻转一次
```

配合延时即可实现 LED 闪烁。

## 十、Makefile进一步优化

之前的 Makefile 主要针对一个 `start.S` 文件。

今天加入了：

```
start.S
main.c
```

两个源文件。

首先定义交叉编译工具：

```
COMPLITER = arm-linux-gnueabihf-

CC = $(COMPLITER)gcc
LD = $(COMPLITER)ld
OBJCOPY = $(COMPLITER)objcopy
OBJDUMP = $(COMPLITER)objdump
```

这样后面不需要重复书写：

```
arm-linux-gnueabihf-
```

---

## 十一、Makefile中的目标文件

定义：

```
OBJS = start.o main.o
TARGET = led
```

表示：

```
OBJS
 ↓
start.o
main.o
```

最终目标程序名称为：

```
led
```

因此最终可以得到：

```
led.elf
led.bin
led.dis
```

---

## 十二、Makefile模式规则

今天进一步学习了 Makefile 的模式规则。

### 1. 编译S文件

```
%.o : %.S
	$(CC) -c $^ -o $@ -g
```

表示：

```
.S
 ↓
.o
```

---

### 2. 编译C文件

```
%.o : %.c
	$(CC) -c $^ -o $@ -g
```

表示：

```
.c
 ↓
.o
```

这样以后增加新的 C 文件时，不需要为每一个文件单独编写编译命令。

---

## 十三、Makefile链接过程

最终目标：

```
$(TARGET).bin : $(OBJS)
	$(LD) -Ttext 0x87800000 $^ -o $(TARGET).elf
	$(OBJCOPY) -O binary -S -g $(TARGET).elf $@
	$(OBJDUMP) -D $(TARGET).elf > $(TARGET).dis
```

整体过程：

```
start.S ──→ start.o
                 │
main.c  ──→ main.o
                 │
                 ↓
              ld链接
                 ↓
              led.elf
             /       \
            ↓         ↓
       objcopy      objdump
          ↓            ↓
       led.bin      led.dis
```

---

## 十四、Makefile中的clean和load

清理：

```bash
clean:
	rm $(OBJS) $(TARGET).elf $(TARGET).bin $(TARGET).dis -f
```

执行：

```bash
make clean
```

可以删除编译生成的文件。

烧写：

```bash
load:
	./imxdownload $(TARGET).bin /dev/sdb
```

执行：

```bash
make load
```

即可将：

```
led.bin
```

烧写到：

```
/dev/sdb
```

## 十七、使用SDK访问GPIO

使用 SDK 后，原来的：

```
#define GPIO1_DR *((unsigned int *)0x0209C000)
#define GPIO1_GDIR *((unsigned int *)0x0209C004)
```

可以简化为：

```
GPIO1->DR
GPIO1->GDIR
```

例如：

```
GPIO1->GDIR |= (1 << 3);
```

点亮 LED：

```
GPIO1->DR &= ~(1 << 3);
```

熄灭 LED：

```
GPIO1->DR |= (1 << 3);
```

代码更加直观。

## 十八、SDK方式初始化LED

使用 SDK 后：

```c
void led_init(void)
{
    IOMUXC_SetPinMux(IOMUXC_GPIO1_IO03_GPIO1_IO03, 0);
    IOMUXC_SetPinConfig(IOMUXC_GPIO1_IO03_GPIO1_IO03, 0x10B0);
    GPIO1->GDIR |= (1 << 3);
}
```

与之前直接操作寄存器相比：

```
直接操作寄存器
 ↓
需要自己查地址
 ↓
自己定义宏
 ↓
自己管理寄存器

SDK方式
 ↓
使用已经定义好的接口
 ↓
代码更加简洁
```

## 二十五、链接脚本

今天还学习了：

```
imx6ull.lds
```

它是链接脚本。

链接脚本主要用于：

> 告诉链接器程序中的代码段、数据段应该如何组织，以及放置到什么地址。

可以把链接脚本理解成：

```
程序内存布局的“蓝图”
```

---

## 二十六、链接脚本中的SECTIONS

基本形式：

```
SECTIONS
{
    ...
}
```

用于描述最终程序中不同段的位置和排列方式。

链接脚本主要包含：

```
.text
.rodata
.data
.bss
COMMON
```

---

## 二十七、代码段.text

链接脚本：

```
.text :
{
    obj/start.o
    *(.text)
}
```

`.text` 主要用于存放程序代码。

起始地址：

```
. = 0x87800000;
```

因此程序从：

```
0x87800000
```

开始放置。

---

## 二十八、只读数据段.rodata

```
.rodata ALIGN(4) : {*(.rodata*)}
```

`.rodata` 用于保存程序中的只读数据。

典型内容包括：

```
字符串常量
const全局变量
只读数组
部分常量数据
```

例如：

```
const int MAX_VALUE = 100;
```

以及：

```
char *str = "Hello World";
```

中的字符串常量，都可能进入只读数据区域。

---

## 二十九、已初始化数据段.data

```
.data ALIGN(4) : {*(.data)}
```

`.data` 用于存放：

> 已经初始化，并且初始值不为0的全局变量和静态变量。

例如：

```
int global_var = 100;
```

以及：

```c
int global_array[] = {1, 2, 3};
```

这些数据需要在程序文件中保存其初始值。

---

## 三十、.bss段

`.bss` 用于存放：

> 未初始化或者初始化为0的全局变量、静态变量等。

例如：

```
static int bss_var;
```

以及：

```
int explicit_var = 0;
```

`.bss` 的一个重要特点是：

```
程序启动时需要清零
```

因此启动代码需要在进入正常程序运行之前完成 `.bss` 的初始化。

---

## 三十一、COMMON段

COMMON 段主要用于：

> 未初始化的非静态全局变量。

例如：

```
int common_var;
```

COMMON 段的大小和最终位置可以在链接阶段确定。

在链接脚本中：

```
.bss ALIGN(4) : {*(.bss) *(.COMMON)}
```

可以将：

```
.bss
COMMON
```

统一放入 `.bss` 区域进行处理。

---

## 三十二、内存段之间的区别

| 段 | 主要存放内容 | 是否需要保存初始值 | 运行时 |
| --- | --- | --- | --- |
| `.text` | 程序代码 | 是 | 通常只读 |
| `.rodata` | 只读数据、字符串等 | 是 | 只读 |
| `.data` | 已初始化全局/静态变量 | 是 | 可写 |
| `.bss` | 未初始化或初始化为0的数据 | 不需要保存具体初值 | 可写 |
| `COMMON` | 未初始化非静态全局变量 | 不需要 | 可写 |

---

## 三十三、为什么要初始化.bss和COMMON

`.bss` 和 `COMMON` 不需要在最终程序中保存大量的初始数据。

例如：

```
int a;
```

程序真正运行时需要：

```
a = 0
```

但是没有必要在程序文件中保存大量的0。

因此：

```
程序文件
 ↓
只记录.bss需要占用多大空间
 ↓
启动时统一清零
```

链接脚本中：

```
__bss_start = .;

.bss ALIGN(4) :
{
    *(.bss)
    *(.COMMON)
}

__bss_end = .;
```

定义了：

```
__bss_start
 ↓
.bss开始地址

__bss_end
 ↓
.bss结束地址
```

启动阶段就可以根据这两个地址对整个区域进行清零。

---

## 三十四、ALIGN(4)

链接脚本中经常出现：

```
ALIGN(4)
```

表示按照4字节进行地址对齐。

例如：

```
.rodata ALIGN(4)
.data ALIGN(4)
.bss ALIGN(4)
```

可以使这些数据段按照4字节边界进行排列。

由于 ARM 处理器经常进行 32 位数据访问，因此合理的数据对齐非常重要。

---

## 三十五、链接脚本中的通配符

例如：

```
*(.rodata*)
```

这里存在两个 `*` 的含义。

第一个：

```
*
```

表示收集所有输入目标文件中的对应段。

第二个：

```
.rodata*
```

表示匹配所有以 `.rodata` 开头的段。

例如：

```
.rodata
.rodata.str1.1
.rodata.str1.4
.rodata.cst4
.rodata.cst8
```

都可以被匹配。

类似地：

```
*(.text*)
```

可以匹配代码相关段。

```
*(.data*)
```

可以匹配数据相关段。
