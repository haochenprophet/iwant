## 一、主要内容

今天主要学习 IIC（I²C）通信，以及 i.MX6ULL 使用 IIC 与 AT24C08 EEPROM 进行数据读写。

主要内容：

1. IIC 通信协议；
2. SDA 和 SCL；
3. IIC 的起始和停止条件；
4. ACK 和 NACK；
5. IIC 设备地址；
6. IIC 数据传输格式；
7. i.MX6ULL I2C1；
8. I2CR、I2SR、I2DR 寄存器；
9. AT24C08 EEPROM；
10. AT24C08 数据读写流程。

---

## 二、什么是IIC

IIC：

> Inter-Integrated Circuit

也写作：

> I²C

是一种常用的**同步串行通信总线**。

IIC 只需要两根主要信号线：

```
SDA —— 数据线
SCL —— 时钟线
```

其中：

- SDA：Serial Data，串行数据线
- SCL：Serial Clock，串行时钟线

基本结构：

```
        SCL ────────────────┐
                            │
CPU / 主机                  │
        SDA ────────────────┼──── 从设备1
                            ├──── 从设备2
                            └──── 从设备3
```

多个设备可以连接在同一条 IIC 总线上。

---

## 三、IIC通信特点

IIC 具有以下特点：

#### 1. 两根信号线

```
SDA
SCL
```

因此可以减少硬件连接数量。

#### 2. 同步通信

SCL 提供同步时钟。

```
SCL → 提供时钟
SDA → 传输数据
```

#### 3. 半双工通信

数据通过 SDA 线进行传输，发送和接收不能同时进行。

#### 4. 多设备共享总线

多个 IIC 设备可以连接到同一组 SDA、SCL。

每个设备通过自己的地址进行区分。

---

## 四、SDA和SCL

### 1. SDA

SDA 是数据线。

数据通过 SDA 进行传输：

```
SDA
 ↓
0 / 1
 ↓
组成数据
```

---

### 2. SCL

SCL 是时钟线。

用于控制数据传输的时序：

```
SCL
 ↑
提供同步时钟
```

因此可以简单记忆：

> **SDA负责传数据，SCL负责提供时钟。**

---

## 五、IIC为什么需要起始和停止条件

IIC 一次完整的数据通信通常需要：

```
START
 ↓
设备地址
 ↓
数据
 ↓
STOP
```

其中：

```
START → 开始一次通信
STOP  → 结束一次通信
```

---

## 六、IIC起始条件 START

IIC 的 START 条件：

> 当 SCL 保持高电平时，SDA 从高电平变为低电平。

表示：

```
SCL = 1
SDA：1 → 0
```

可以理解为：

```
SCL ─────────────
       ┌────
SDA ───┘
```

出现 START 后，表示：

> 主机开始进行一次 IIC 通信。

---

## 七、IIC停止条件 STOP

STOP 条件与 START 相反。

当：

```
SCL = 1
```

时：

```
SDA：0 → 1
```

表示 STOP。

即：

```
SCL ─────────────
SDA ────┐
        └────────
```

表示：

> 本次 IIC 通信结束。

---

## 八、ACK应答

IIC 每发送一个字节后，都需要进行应答。

ACK：

> Acknowledge，应答。

一个字节：

```
8 bit
```

发送完成以后，第 9 个时钟用于 ACK。

基本过程：

```
发送8位数据
     ↓
第9个时钟
     ↓
接收方发送ACK
```

因此：

```
8bit数据 + 1bit ACK
```

构成一个完整的字节传输过程。

---

## 九、NACK

NACK：

> Not Acknowledge，无应答。

如果接收方不发送 ACK，则表示 NACK。

在读取多个字节时，主机读取最后一个字节后通常会发送 NACK，告诉从设备：

> 数据读取结束。

因此：

```
ACK  → 继续通信
NACK → 通常表示不再继续
```

---

## 十、IIC设备地址

IIC 总线上可以存在多个设备，因此需要通过地址区分不同设备。

例如 AT24C08 的设备地址可以使用：

```
0x50
```

因此主机需要先发送：

```
设备地址
```

告诉总线上的设备：

> 我要与地址为 0x50 的设备通信。

---

## 十一、读写位

IIC 地址传输过程中还需要包含读写控制位。

基本形式：

```
7位设备地址 + 1位R/W
```

其中：

```
R/W = 0 → 写
R/W = 1 → 读
```

例如设备地址：

```
0x50
```

写操作：

```
0x50 << 1
```

然后最低位：

```
0
```

读操作：

```
0x50 << 1
```

然后最低位：

```
1
```

因此：

```
写地址 = (0x50 << 1) | 0
读地址 = (0x50 << 1) | 1
```

---

## 十二、IIC基本通信格式

一次典型的 IIC 写操作：

```
START
 ↓
设备地址 + W
 ↓
ACK
 ↓
寄存器/存储地址
 ↓
ACK
 ↓
数据
 ↓
ACK
 ↓
STOP
```

可以记成：

```
开始
 ↓
找设备
 ↓
告诉设备操作哪个地址
 ↓
发送数据
 ↓
结束
```

---

## 十三、IIC读操作

IIC 读取 EEPROM 数据时，通常需要先告诉 EEPROM：

> 我要读取哪个存储地址。

因此读取过程不是简单的“直接读”。

典型流程：

```
START
 ↓
设备地址 + W
 ↓
ACK
 ↓
发送内部存储地址
 ↓
ACK
 ↓
重复START
 ↓
设备地址 + R
 ↓
ACK
 ↓
读取数据
 ↓
NACK
 ↓
STOP
```

这里有一个非常重要的操作：

```
重复START
Repeated START
```

---

## 十四、为什么读取EEPROM需要先写地址

AT24C08 内部有很多存储单元。

主机必须告诉它：

```
我要读取哪个存储位置？
```

所以先进行：

```
设备地址 + W
 ↓
发送内部地址
```

这一步并不是把用户数据写入 EEPROM，而是：

> 设置接下来要读取的内部存储地址。

然后：

```
Repeated START
 ↓
设备地址 + R
 ↓
读取数据
```

---

## 十五、AT24C08

AT24C08 是一种：

> IIC 接口 EEPROM。

EEPROM：

> Electrically Erasable Programmable Read-Only Memory

即：

> 电可擦除可编程只读存储器。

它的特点是：

```
断电后数据仍然可以保存
```

因此非常适合保存：

```
配置参数
设备参数
用户设置
校准数据
少量永久数据
```

---

## 十六、AT24C08的地址

实验中使用的设备地址为：

```
0x50
```

因此程序中可以看到：

```
0x50
```

作为从设备地址。

例如：

```
i2c_write(I2C1, 0x50, ...);
```

这里的：

```
0x50
```

就是 AT24C08 的 IIC 设备地址。

---

## 十七、AT24C08写数据

AT24C08 写数据的基本流程：

```
START
 ↓
设备地址 + W
 ↓
ACK
 ↓
存储地址
 ↓
ACK
 ↓
数据
 ↓
ACK
 ↓
STOP
```

例如：

```
主机
 ↓
START
 ↓
0x50 + W
 ↓
存储地址
 ↓
数据
 ↓
STOP
```

写入完成后，AT24C08 需要一定的内部写周期。

所以连续操作时不能假设数据一发送完就立刻可以进行下一次访问。

---

## 十八、AT24C08读数据

读取数据：

```
START
 ↓
0x50 + W
 ↓
ACK
 ↓
内部存储地址
 ↓
ACK
 ↓
重复START
 ↓
0x50 + R
 ↓
ACK
 ↓
读取数据
 ↓
NACK
 ↓
STOP
```

重点记忆：

> **EEPROM随机读取通常需要先发送内部存储地址，再通过重复 START 切换到读操作。**

## 十九、i.MX6ULL的I2C1

i.MX6ULL 内部提供 I2C 控制器。

实验使用：

```
I2C1
```

主要涉及：

```
SDA
SCL
```

在当前实验中，I2C1 对应的引脚进行了复用配置。

使用：

```
UART4_RX_DATA → I2C1_SDA
UART4_TX_DATA → I2C1_SCL
```

也就是说，这些引脚通过 IOMUX 配置后，可以作为 I2C1 的 SDA 和 SCL。

---

## 二十、IOMUX引脚复用

i.MX6ULL 的一个引脚通常具有多种复用功能。

例如一个引脚既可以作为：

```
UART
```

也可以作为：

```
I2C
```

所以使用 I2C 前，需要先配置 IOMUX。

基本流程：

```
GPIO默认功能
      ↓
配置IOMUX
      ↓
选择I2C功能
      ↓
引脚成为SDA/SCL
```

---

## 二十一、I2C主要寄存器

i.MX6ULL I2C 控制器中需要重点掌握：

```
I2CR
I2SR
I2DR
```

---

### 1. I2CR

I2CR：

> I2C Control Register

即：

> I2C控制寄存器。

主要用于：

```
使能I2C
设置主从模式
启动传输
产生START/STOP
中断相关控制
```

---

### 2. I2SR

I2SR：

> I2C Status Register

即：

> I2C状态寄存器。

主要用于查看 I2C 当前状态。

例如：

```
发送完成
接收到ACK
总线状态
```

---

### 3. I2DR

I2DR：

> I2C Data Register

即：

> I2C数据寄存器。

发送数据时：

```
CPU
 ↓
I2DR
 ↓
I2C控制器
 ↓
SDA
```

接收数据时：

```
SDA
 ↓
I2C控制器
 ↓
I2DR
 ↓
CPU
```

---

## 二十二、I2C初始化

I2C 初始化主要完成：

```
① 引脚复用
② 配置I2C时钟
③ 设置分频
④ 使能I2C控制器
⑤ 配置相关控制位
```

当前实验中 I2C1 使用：

```
I2C1
```

并通过：

```
IFDR
```

配置 I2C 时钟分频。

---

## 二十三、IFDR分频器

IFDR：

> I2C Frequency Divider Register

用于设置 I2C 的时钟分频。

实验代码中使用：

```
I2C1->IFDR = 0x15;
```

其作用是对 I2C 输入时钟进行分频，从而得到合适的 I2C 总线时钟。

I2C 总线速度需要由：

```
输入时钟
+
IFDR分频
```

共同决定。

---

## 二十四、IIC写函数

实验中的写函数可以抽象为：

```
i2c_write(I2C1,
          0x50,
          0,
          1,
          data,
          size);
```

参数可以理解为：

```
I2C1
 ↓
使用哪个I2C控制器

0x50
 ↓
从设备地址

0
 ↓
内部存储地址

1
 ↓
内部地址长度

data
 ↓
要写入的数据

size
 ↓
数据长度
```

因此，一个完整的 I2C 写函数通常需要知道：

```
I2C控制器
设备地址
内部存储地址
地址长度
数据
数据长度
```

---

## 二十五、IIC读函数

读函数的参数与写函数类似：

```
I2C控制器
+
设备地址
+
内部地址
+
地址长度
+
接收数据缓冲区
+
数据长度
```

典型流程：

```
设置内部地址
      ↓
START
      ↓
设备地址+W
      ↓
发送内部地址
      ↓
重复START
      ↓
设备地址+R
      ↓
接收数据
      ↓
NACK
      ↓
STOP
```

## 二十六、字符串写入EEPROM时需要注意长度

如果程序通过：

```
scanf()
```

输入字符串：

```
hello
```

那么实际字符数量是：

```
5
```

如果作为 C 字符串保存，还需要：

```
'\0'
```

所以缓冲区中实际可能是：

```
h e l l o \0
```

长度计算通常使用：

```
strlen(data)
```

然后将实际长度传递给 I2C 写函数。

---

## 二十七、为什么读取最后一个字节容易出现问题

I2C 接收数据时，最后一个字节的处理和前面的字节不同。

连续读取多个字节：

```
数据1 → ACK
数据2 → ACK
数据3 → ACK
...
最后数据 → NACK
```

最后一个字节发送 NACK 的意义是：

> 告诉从设备：我已经读取完毕，不需要继续发送。

然后：

```
STOP
```

结束本次通信。

因此读取代码中：

```
ACK/NACK
```

的处理非常重要。

## 二十九、IIC和串口的区别

IIC 与之前学习的 UART 都属于串行通信，但是工作方式不同。

| 对比 | IIC | UART |
| --- | --- | --- |
| 信号线 | SDA、SCL | TX、RX |
| 时钟 | 有独立SCL | 无独立时钟线 |
| 通信方式 | 同步 | 异步 |
| 设备寻址 | 有设备地址 | 通常没有总线设备地址 |
| 总线结构 | 多设备共享 | 通常点对点 |
| ACK | 有 | 没有IIC这种ACK机制 |
| 常见用途 | EEPROM、传感器 | PC通信、模块通信 |

可以记成：

```
UART：
TX/RX
异步
点对点

IIC：
SDA/SCL
同步
多设备共享
```
