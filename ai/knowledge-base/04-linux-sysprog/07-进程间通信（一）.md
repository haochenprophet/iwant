## 一、什么是进程间通信

进程间通信，简称：

```
IPC
Inter-Process Communication
```

就是：

> **不同进程之间进行数据交换和同步的一种机制。**

例如：

```
 进程A
   │
   │ 发送数据
   ↓
IPC机制
   │
   │ 接收数据
   ↓
 进程B
```

常见的进程间通信方式：

```
进程间通信
│
├── 管道 Pipe
│
├── 有名管道 FIFO
│
├── 消息队列
│
├── 共享内存
│
├── 信号
│
└── Socket
```

本章重点掌握：

> **管道、FIFO、消息队列、共享内存、信号。**

---

## 二、为什么进程之间不能直接通信

假设有两个进程：

```
进程A                       进程B
┌──────────┐              ┌──────────┐
│ int num; │              │ int num; │
│          │              │          │
│ 地址空间 │              │ 地址空间 │
└──────────┘              └──────────┘
```

即使两个进程中都有：

```
int num;
```

它们也不是同一个变量。

例如：

```
进程A：
num = 100

进程B：
num = 200
```

两个 `num` 分别属于不同的进程地址空间。

因此需要：

```
进程A
 ↓
IPC
 ↓
进程B
```

---

## 三、进程间通信的主要方式

可以先记住这一张表：

| IPC方式 | 特点 | 常见用途 |
| --- | --- | --- |
| 管道 | 单向、亲缘进程 | 父子进程通信 |
| FIFO | 有名管道、无亲缘关系也可以 | 不相关进程通信 |
| 消息队列 | 按消息进行通信 | 结构化消息传递 |
| 共享内存 | 速度快 | 大量数据交换 |
| 信号 | 传递事件/通知 | 异步通知 |
| Socket | 网络/本机通信 | 网络程序 |

---

## 四、管道 Pipe

管道是 Linux 中最经典的 IPC 方式之一。

基本特点：

> **管道是一种半双工通信机制。**

所谓半双工：

```
A ─────────→ B
```

数据主要沿一个方向流动。

---

## 五、管道的基本结构

```
 写端                    读端
  │                       │
  ↓                       ↓
进程A                   进程B
  │                       │
  └──────→ 管道 ←─────────┘
```

例如：

```
进程A
  │
write()
  │
  ↓
┌──────────┐
│  管道     │
└──────────┘
  │
read()
  ↓
进程B
```

---

## 六、pipe() 创建管道

函数：

```
pipe()
```

头文件：

```
#include <unistd.h>
```

函数原型：

```
int pipe(int pipefd[2]);
```

调用：

```
int pipefd[2];

pipe(pipefd);
```

创建成功以后：

```
pipefd[0]
    ↓
读端

pipefd[1]
    ↓
写端
```

一定要记住：

```
pipefd[0] → read
pipefd[1] → write
```

---

## 七、pipe() 的工作原理

执行：

```
int pipefd[2];

pipe(pipefd);
```

系统创建一个管道，并返回两个文件描述符：

```
pipefd[0] ───────→ 读端
pipefd[1] ───────→ 写端
```

因此：

```
read(pipefd[0], ...);
```

表示从管道读取。

```
write(pipefd[1], ...);
```

表示向管道写入。

---

## 八、父子进程通过管道通信

管道最典型的应用：

```
父进程
  │
  │ fork()
  ↓
子进程
```

因为 `fork()` 后，子进程会继承父进程打开的文件描述符。

所以：

```
父进程 ─────┐
            │
            ↓
          管道
            ↑
            │
子进程 ─────┘
```

双方都可以拥有管道的读写端。

---

## 九、单向通信的典型结构

例如：

```
父进程                    子进程
   │                        │
   │ write                  │
   ├──────────────→        │
   │                       read
   │                        │
```

父进程：

```
写数据
 ↓
pipe
 ↓
子进程读取
```

---

## 十、父子进程管道通信示例

```c
#include <stdio.h>
#include <unistd.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <string.h>

int main(void)
{
    int pipefd[2] = {0};
    pid_t pid = 0;
    char buf[1024] = {0};

    pipe(pipefd);

    pid = fork();

    if(pid < 0)
    {
        perror("fork");
        return -1;
    }

    if(pid == 0)
    {
        // 子进程关闭写端
        close(pipefd[1]);

        read(pipefd[0], buf, sizeof(buf));

        printf("子进程收到：%s\n", buf);

        close(pipefd[0]);
    }
    else
    {
        // 父进程关闭读端
        close(pipefd[0]);

        strcpy(buf, "hello child");

        write(pipefd[1], buf, strlen(buf) + 1);

        close(pipefd[1]);

        wait(NULL);
    }

    return 0;
}
```

运行：

```
子进程收到：hello child
```

---

## 十一、为什么要关闭不用的管道端

例如父进程只负责写：

```
父进程：
write
```

那么应该：

```
close(pipefd[0]);
```

关闭读端。

子进程只负责读：

```
子进程：
read
```

应该：

```
close(pipefd[1]);
```

关闭写端。

结构：

```
父进程
 ├── 关闭读端
 └── 使用写端

子进程
 ├── 关闭写端
 └── 使用读端
```

这样做可以：

- 避免文件描述符泄漏
- 明确通信方向
- 正确判断管道 EOF
- 让程序逻辑更加清晰

---

## 十二、管道为什么通常用于父子进程

因为：

```
pipe()
```

创建的是内核中的一个管道对象。

随后：

```
fork()
```

子进程继承父进程的文件描述符。

所以：

```
pipe()
 ↓
fork()
 ↓
父子进程共同拥有管道描述符
 ↓
可以通信
```

因此：

> **匿名管道特别适合具有亲缘关系的进程之间通信。**

---

## 十三、管道的读写特性

管道本质上可以理解为：

```
内核中的一个缓冲区
```

写入：

```
write()
 ↓
管道缓冲区
```

读取：

```
管道缓冲区
 ↓
read()
```

因此数据通常具有：

> **先进先出（FIFO）**

的特点。

---

## 十四、管道的阻塞

如果管道中没有数据：

```
read()
 ↓
没有数据
 ↓
阻塞等待
```

如果管道已经没有空间：

```
write()
 ↓
管道满
 ↓
阻塞等待
```

这也是管道能够天然用于进程同步的原因之一。

---

## 十五、管道的局限性

匿名管道存在一些限制：

#### 1. 通常用于具有亲缘关系的进程

例如：

```
父子进程
兄弟进程
```

#### 2. 通常是半双工通信

如果需要双向通信，可以创建两个管道：

```
管道1：
A → B

管道2：
B → A
```

形成：

```
      管道1
A ─────────→ B

      管道2
A ←───────── B
```

---

## 十六、有名管道 FIFO

如果两个进程没有亲缘关系怎么办？

例如：

```
进程A

进程B
```

它们不是：

```
父子关系
```

这时候可以使用：

> **有名管道 FIFO（Named Pipe）**

---

## 十七、FIFO 和匿名管道的区别

匿名管道：

```
pipe()
```

通常：

```
亲缘进程
```

FIFO：

```
mkfifo()
```

可以：

```
无亲缘关系的进程
```

通信。

对比：

| 项目 | 匿名管道 | FIFO |
| --- | --- | --- |
| 创建 | `pipe()` | `mkfifo()` |
| 文件系统中是否有名字 | 没有 | 有 |
| 是否需要亲缘关系 | 通常需要 | 不需要 |
| 通信方式 | 文件描述符 | 文件 |
| 典型应用 | 父子进程 | 独立程序之间 |

---

## 十八、mkfifo()

创建 FIFO：

```
mkfifo()
```

头文件：

```
#include <sys/types.h>
#include <sys/stat.h>
```

函数：

```
int mkfifo(
    const char *pathname,
    mode_t mode
);
```

例如：

```
mkfifo("/tmp/Myfifo", 0664);
```

执行以后：

```
/tmp/Myfifo
```

会成为一个 FIFO 特殊文件。

可以使用：

```bash
ls -l /tmp/Myfifo
```

查看。

---

## 十九、FIFO 通信结构

```
进程A
  │
open("/tmp/Myfifo", O_WRONLY)
  │
write()
  ↓
┌─────────────────┐
│ /tmp/Myfifo     │
│     FIFO        │
└─────────────────┘
  ↑
read()
  │
open("/tmp/Myfifo", O_RDONLY)
  │
进程B
```

两个程序甚至可以完全独立运行。

---

## 二十、FIFO 的典型应用

例如：

```
writer.c
```

负责：

```
写入数据
```

另一个：

```
reader.c
```

负责：

```
读取数据
```

它们之间通过：

```
/tmp/Myfifo
```

通信。

这也是 Linux 中非常典型的：

> **无亲缘关系进程通信。**

---

## 二十、信号 Signal

信号也是 Linux 中一种重要的 IPC 机制。

但是信号与：

```
管道
消息队列
共享内存
```

不同。

信号主要用于：

> **通知某个进程发生了某个事件。**

例如：

```
进程A
 ↓
发送信号
 ↓
进程B
 ↓
执行信号处理函数
```

---

## 四十、常见信号

Linux 中常见：

```
SIGINT
SIGTERM
SIGKILL
SIGSTOP
SIGCHLD
SIGUSR1
SIGUSR2
```

---

## 二十一、Ctrl+C 和 SIGINT

在终端运行：

```bash
./a.out
```

按：

```
Ctrl + C
```

通常会产生：

```
SIGINT
```

发送给前台进程。

可以理解成：

```
键盘
 ↓
Ctrl+C
 ↓
SIGINT
 ↓
进程
```

---

## 四十二、kill()

发送信号可以使用：

```
kill()
```

函数原型：

```
int kill(pid_t pid, int sig);
```

例如：

```
kill(pid, SIGUSR1);
```

表示：

> 向指定 PID 的进程发送 `SIGUSR1` 信号。

注意：

> `kill()` 不一定意味着“杀死进程”。

它本质上是：

> **向指定进程发送一个信号。**

---

## 二十三、signal()

可以使用：

```
signal()
```

设置简单的信号处理方式。

例如：

```
signal(SIGINT, handler);
```

当进程收到：

```
SIGINT
```

就执行：

```
handler()
```

---

## 二十四、信号处理函数

例如：

```c
#include <stdio.h>
#include <signal.h>

void handler(int sig)
{
    printf("收到信号：%d\n", sig);
}

int main(void)
{
    signal(SIGINT, handler);

    while(1)
    {
    }

    return 0;
}
```

运行：

```bash
./a.out
```

按：

```
Ctrl+C
```

可能输出：

```
收到信号：2
```

之后程序不会因为默认处理动作而立即退出，因为我们设置了自己的处理函数。

---

## 二十五、SIGKILL和SIGSTOP特殊在哪里

有两个信号不能被进程捕获、阻塞或忽略：

```
SIGKILL
SIGSTOP
```

例如：

```
kill -9 PID
```

其中：

```
9
 ↓
SIGKILL
```

表示强制终止进程。

---

## 二十六、进程间通信方式对比

把本章内容放在一起：

```
          进程间通信 IPC
                 │
  ┌──────────────┼──────────────┐
  ↓              ↓              ↓
管道            FIFO          消息队列
  │              │              │
字节流        有名管道        消息单位
  │              │              │
  └──────────────┼──────────────┘
                 ↓
             共享内存
                 │
               速度快
                 │
                 ↓
               信号
                 │
               事件通知
```

---

## 二十七、各种 IPC 的特点

#### 1. 管道

```
pipe()
```

特点：

- 简单
- 常用于父子进程
- 半双工
- 字节流

---

#### 2. FIFO

```
mkfifo()
```

特点：

- 有名字
- 存在于文件系统
- 无亲缘关系进程也能通信
- 常用于两个独立程序

---

#### 3. 信号

```
kill()
signal()
```

特点：

- 数据量小
- 主要用于事件通知
- 异步
- 可以通知进程发生某个事件

---

## 二十八、进程间通信和线程间通信对比

| 项目 | 线程间 | 进程间 |
| --- | --- | --- |
| 地址空间 | 共享 | 独立 |
| 数据共享 | 方便 | 需要 IPC |
| 共享变量 | 可以直接使用 | 不能直接共享普通变量 |
| 互斥锁 | 常用 | 也可以使用进程共享属性的同步机制 |
| 条件变量 | 常用 | 可以配置为进程共享 |
| 信号量 | 可以 | 可以 |
| 管道 | 一般不是首选 | 常用 |
| FIFO | 一般不是首选 | 常用 |
| 消息队列 | 不常作为首选 | 常用 |
| 共享内存 | 不需要 | 常用 |

核心区别：

```
线程：
共享地址空间
     ↓
直接共享数据
     ↓
重点解决同步问题

进程：
地址空间独立
     ↓
需要IPC交换数据
     ↓
重点解决通信 + 同步
```
