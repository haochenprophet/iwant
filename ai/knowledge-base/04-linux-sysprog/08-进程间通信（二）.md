## 一 、消息队列

消息队列（Message Queue）是一种：

> **以消息为单位进行进程间通信的机制。**

可以理解成系统维护了一个“消息仓库”：

```
进程A
  │
  │ msgsnd()
  ↓
┌─────────────────┐
│    消息队列      │
├─────────────────┤
│ 消息1            │
│ 消息2            │
│ 消息3            │
└─────────────────┘
        │
        │ msgrcv()
        ↓
      进程B
```

与管道最大的区别之一：

```
管道：
    字节流

消息队列：
    一条一条的消息
```

因此消息队列更适合：

> **结构化地传递消息。**

---

## 二、消息队列的特点

消息队列具有以下特点：

#### ① 以消息为单位

例如：

```
消息1：hello
消息2：123
消息3：quit
```

而不是简单的一串字节。

#### ② 可以指定消息类型

接收进程可以根据：

```
msgtyp
```

选择自己需要的消息。

#### ③ 消息队列存在于内核中

不是简单的用户空间数组。

#### ④ 不要求通信双方同时执行

发送进程把消息放入队列后，接收进程之后可以再读取。

---

## 三、消息队列的基本流程

消息队列主要使用：

```
ftok()
   ↓
msgget()
   ↓
msgsnd()
   ↓
msgrcv()
   ↓
msgctl()
```

---

## 四、ftok()

函数原型：

```
key_t ftok(const char *pathname, int proj_id);
```

作用：

> **根据路径名和项目 ID 生成 IPC 的 key。**

课程资料中说明，`ftok()` 根据目录名和项目 ID 生成 IPC 对象名称（key）。

例如：

```
key_t key;

key = ftok("/tmp", 'a');
```

这里：

```
/tmp
 ↓
pathname

'a'
 ↓
proj_id

 ↓

key
```

---

## 五、为什么需要 key

进程 A：

```
创建消息队列
```

进程 B：

```
获取消息队列
```

两个进程必须知道：

> **“我们要操作的是哪一个消息队列？”**

所以需要一个共同的标识：

```
key
 ↓
消息队列
```

例如：

```
进程A ──┐
        ├── key ──→ 同一个消息队列
进程B ──┘
```

---

## 六、msgget()

函数：

```
int msgget(key_t key, int msgflg);
```

作用：

> **创建或者获取一个消息队列。**

参数包括：

```
key
IPC_CREAT
IPC_EXCL
```

成功返回：

```
消息队列 ID
```

失败返回：

```
-1
```

例如：

```
int msgid;

msgid = msgget(key, IPC_CREAT | 0666);
```

这里：

```
IPC_CREAT
```

表示：

> 如果消息队列不存在，就创建。

---

## 七、消息队列 ID 和 key 的区别

这两个非常容易混淆。

```
key
 ↓
用于找到 IPC 对象

msgid
 ↓
真正操作消息队列时使用
```

例如：

```
key = ftok("/tmp", 'a');

msgid = msgget(key, IPC_CREAT | 0666);
```

后面的：

```
msgsnd(msgid, ...);
msgrcv(msgid, ...);
```

使用的是：

```
msgid
```

而不是：

```
key
```

---

## 八、消息结构体

使用 System V 消息队列时，一般定义：

```c
struct msgbuf
{
    long mtype;
    char mtext[1024];
};
```

例如：

```
struct msgbuf msg;
```

其中：

```
mtype
 ↓
消息类型

mtext
 ↓
消息内容
```

特别注意：

> `mtype` 必须是 `long` 类型，而且必须是正数。

---

## 九、msgsnd()

函数原型：

```
int msgsnd(
    int msqid,
    const void *msgp,
    size_t msgsz,
    int msgflg
);
```

作用：

> **向消息队列发送消息。**

`msgsnd()` 的 `msgp` 是发送消息空间的首地址，`msgsz` 是发送消息内容的大小。

例如：

```
struct msgbuf msg;

msg.mtype = 100;
strcpy(msg.mtext, "hello");

msgsnd(
    msgid,
    &msg,
    strlen(msg.mtext) + 1,
    0
);
```

---

## 十、为什么 msgsz 不包含 mtype

这是一个非常重要的细节。

结构：

```c
struct msgbuf
{
    long mtype;
    char mtext[1024];
};
```

发送：

```
msgsnd(
    msgid,
    &msg,
    strlen(msg.mtext) + 1,
    0
);
```

这里的大小是：

```
mtext 的大小
```

不是：

```
sizeof(struct msgbuf)
```

因为：

> `mtype` 不属于消息正文大小。

---

## 十一、msgrcv()

函数：

```
ssize_t msgrcv(
    int msqid,
    void *msgp,
    size_t msgsz,
    long msgtyp,
    int msgflg
);
```

作用：

> **从消息队列中接收消息。**

- `msqid`：消息队列 ID
- `msgp`：存放消息的空间首地址
- `msgsz`：最多接收的数据大小
- `msgtyp`：接收的消息类型
- 成功返回实际接收的字节数
- 失败返回 `-1`

---

## 十二、消息类型 mtype

例如发送：

```
msg.mtype = 100;
```

接收：

```
msgrcv(msgid, &msg, sizeof(msg.mtext), 100, 0);
```

表示：

> 接收类型为 `100` 的消息。

可以设计成：

```
类型100
 ↓
普通聊天消息

类型200
 ↓
控制消息

类型300
 ↓
退出消息
```

这样一个消息队列就可以承载不同类型的信息。

---

## 十三、消息队列发送程序

例如 `send.c`：

```c
#include <stdio.h>
#include <string.h>
#include <sys/types.h>
#include <sys/ipc.h>
#include <sys/msg.h>

struct msgbuf
{
    long mtype;
    char mtext[1024];
};

int main(void)
{
    key_t key;
    int msgid;
    struct msgbuf msg;

    key = ftok("/tmp", 'a');

    if(key == -1)
    {
        perror("ftok");
        return -1;
    }

    msgid = msgget(key, IPC_CREAT | 0666);

    if(msgid == -1)
    {
        perror("msgget");
        return -1;
    }

    while(1)
    {
        memset(&msg, 0, sizeof(msg));

        printf("请输入消息：");
        fgets(msg.mtext, sizeof(msg.mtext), stdin);

        msg.mtype = 100;

        if(msgsnd(msgid,
                   &msg,
                   strlen(msg.mtext) + 1,
                   0) == -1)
        {
            perror("msgsnd");
            return -1;
        }
    }

    return 0;
}
```

## 十四、消息队列接收程序

`recv.c`：

```c
#include <stdio.h>
#include <string.h>
#include <sys/types.h>
#include <sys/ipc.h>
#include <sys/msg.h>

struct msgbuf
{
    long mtype;
    char mtext[1024];
};

int main(void)
{
    key_t key;
    int msgid;
    struct msgbuf msg;

    key = ftok("/tmp", 'a');

    if(key == -1)
    {
        perror("ftok");
        return -1;
    }

    msgid = msgget(key, IPC_CREAT | 0666);

    if(msgid == -1)
    {
        perror("msgget");
        return -1;
    }

    while(1)
    {
        memset(&msg, 0, sizeof(msg));

        if(msgrcv(msgid,
                  &msg,
                  sizeof(msg.mtext),
                  100,
                  0) == -1)
        {
            perror("msgrcv");
            return -1;
        }

        printf("收到消息：%s", msg.mtext);
    }

    return 0;
}
```

运行两个终端：

```bash
./send
```

另一个：

```bash
./recv
```

然后：

```
终端1：
请输入消息：hello

终端2：
收到消息：hello
```

## 十七、共享内存

> **共享内存（Shared Memory）**

共享内存是 IPC 中非常重要的一种方式。

> **共享内存是进程间通信最高效的形式。**

---

## 十八、共享内存的原理

正常情况下：

```
进程A                  进程B
┌─────────┐            ┌─────────┐
│ 地址空间 │            │ 地址空间 │
└─────────┘            └─────────┘
```

两者地址空间相互独立。

使用共享内存后：

```
进程A
   │
   ↓
┌──────────────────┐
│    共享内存       │
└──────────────────┘
   ↑
   │
进程B
```

两个进程都可以访问同一块共享内存。

---

## 十九、共享内存为什么快

例如管道：

```
进程A
 ↓
内核缓冲区
 ↓
进程B
```

共享内存：

```
进程A ──────┐
            ↓
        共享内存
            ↑
            │
进程B ──────┘
```

数据不需要频繁地在进程和内核之间复制。

所以非常适合：

> **大量数据的进程间交换。**

---

## 二十、共享内存的操作流程

```
1. ftok()
      ↓
2. shmget()
      ↓
3. shmat()
      ↓
4. 使用共享内存
      ↓
5. shmdt()
      ↓
6. shmctl()
```

---

## 二十一、shmget()

函数：

```
int shmget(
    key_t key,
    size_t size,
    int shmflg
);
```

作用：

> **创建或者获取共享内存。**

- `key`：IPC 对象名称
- `size`：共享内存大小
- `IPC_CREAT`：不存在就创建
- `IPC_EXCL`：存在则报错
- 成功返回共享内存 ID
- 失败返回 `-1`

例如：

```
int shmid;

shmid = shmget(
    key,
    4096,
    IPC_CREAT | 0666
);
```

表示：

> 创建一个大小为 4096 字节的共享内存。

---

## 二十二、shmat()

共享内存创建之后：

```
shmget()
 ↓
得到 shmid
```

但是还不能直接使用。

需要：

```
shmat()
```

将共享内存映射到当前进程的地址空间。

函数：

```
void *shmat(
    int shmid,
    const void *shmaddr,
    int shmflg
);
```

`shmaddr = NULL` 时由系统选择合适的映射地址。

例如：

```
char *p;

p = shmat(shmid, NULL, 0);
```

成功后：

```
p
 ↓
共享内存首地址
```

于是可以：

```
strcpy(p, "hello");
```

---

## 二十三、shmdt()

使用完成后：

```
shmdt(p);
```

作用：

> **解除当前进程与共享内存的映射关系。**

注意：

```
shmdt()
```

并不是删除共享内存。

只是：

```
当前进程
    ↓
解除映射
```

---

## 二十四、shmctl()

删除共享内存：

```
shmctl(
    shmid,
    IPC_RMID,
    NULL
);
```

其中：

```
IPC_RMID
 ↓
删除共享内存
```

常见命令包括：

```
IPC_STAT
IPC_SET
IPC_RMID
```

---

## 二十五、共享内存简单示例

### 写进程

```c
#include <stdio.h>
#include <string.h>
#include <sys/types.h>
#include <sys/ipc.h>
#include <sys/shm.h>

int main(void)
{
    key_t key;
    int shmid;
    char *p = NULL;

    key = ftok("/tmp", 'a');

    if(key == -1)
    {
        perror("ftok");
        return -1;
    }

    shmid = shmget(
        key,
        4096,
        IPC_CREAT | 0666
    );

    if(shmid == -1)
    {
        perror("shmget");
        return -1;
    }

    p = shmat(shmid, NULL, 0);

    if(p == (void *)-1)
    {
        perror("shmat");
        return -1;
    }

    strcpy(p, "hello shared memory");

    printf("写入完成\n");

    shmdt(p);

    return 0;
}
```

```c
#include <stdio.h>
```

```
相同的 key
```

```
同一块共享内存
```

## 二十七、共享内存最重要的问题

共享内存虽然快，但存在一个问题：

```
进程A：正在写

进程B：同时读
```

可能导致：

```
数据不一致
```

例如：

```
进程A：
正在写 hello

进程B：
同时读取
```

可能读到不完整的数据。

所以：

> **共享内存负责数据共享，但不负责同步。**

通常需要配合：

```
共享内存
+
信号量
```

使用。

---

## 二十八、有名信号量

> **有名信号量（Named Semaphore）**

前面线程间通信学习过：

```
sem_t sem;

sem_init(&sem, 0, 1);
```

这种主要用于：

```
同一进程内的线程
```

或者通过特定方式放入共享内存并设置 `pshared` 来做进程间同步。

而：

> **有名信号量可以通过一个名字让不同进程找到同一个信号量。**

---

## 二十九、为什么共享内存需要信号量

例如：

```
进程A
 ↓
写共享内存
```

同时：

```
进程B
 ↓
读共享内存
```

必须控制：

```
A写完
 ↓
B才能读
```

可以使用：

```
共享内存
+
有名信号量
```

形成：

```
    共享内存
   ↙       ↘
进程A       进程B
   ↑         ↑
   └─信号量──┘
```

---

## 三十、有名信号量的核心函数

POSIX 有名信号量主要使用：

```
sem_open()
sem_wait()
sem_post()
sem_close()
sem_unlink()
```

头文件：

```
#include <semaphore.h>
```

---

## 三十一、sem_open()

函数：

```
sem_t *sem_open(
    const char *name,
    int oflag,
    ...
);
```

例如：

```
sem_t *sem;

sem = sem_open(
    "/mysem",
    O_CREAT,
    0666,
    1
);
```

这里：

```
/mysem
 ↓
信号量的名字

O_CREAT
 ↓
不存在则创建

0666
 ↓
权限

1
 ↓
初始值
```

注意：

> 有名信号量的名字通常以 `/` 开头，例如 `/mysem`。

---

## 三十二、sem_wait()

```
sem_wait(sem);
```

作用：

> **申请信号量。**

假设：

```
信号量 = 1
```

执行：

```
sem_wait(sem);
```

之后：

```
1 → 0
```

线程/进程获得资源。

如果：

```
信号量 = 0
```

那么：

```
sem_wait()
```

会阻塞等待。

---

## 三十三、sem_post()

```
sem_post(sem);
```

作用：

> **释放信号量。**

例如：

```
0
 ↓
sem_post()
 ↓
1
```

等待的进程就可以继续执行。

---

## 三十四、sem_close()

进程使用完有名信号量：

```
sem_close(sem);
```

作用：

> **关闭当前进程对有名信号量的使用。**

注意：

```
sem_close()
```

不等于：

```
删除信号量
```

---

## 三十五、sem_unlink()

真正删除有名信号量：

```
sem_unlink("/mysem");
```

可以理解为：

```
sem_close()
 ↓
当前进程不再使用

sem_unlink()
 ↓
删除有名信号量名字
```

---

## 三十六、有名信号量简单示例

### 进程A

```c
#include <stdio.h>
#include <fcntl.h>
#include <semaphore.h>
#include <unistd.h>

int main(void)
{
    sem_t *sem;

    sem = sem_open(
        "/mysem",
        O_CREAT,
        0666,
        1
    );

    if(sem == SEM_FAILED)
    {
        perror("sem_open");
        return -1;
    }

    sem_wait(sem);

    printf("进程A获得信号量\n");

    sleep(5);

    printf("进程A释放信号量\n");

    sem_post(sem);

    sem_close(sem);

    return 0;
}
```

---

## 三十七、进程B

```c
#include <stdio.h>
#include <fcntl.h>
#include <semaphore.h>
#include <unistd.h>

int main(void)
{
    sem_t *sem;

    sem = sem_open(
        "/mysem",
        O_CREAT,
        0666,
        1
    );

    if(sem == SEM_FAILED)
    {
        perror("sem_open");
        return -1;
    }

    printf("进程B等待信号量...\n");

    sem_wait(sem);

    printf("进程B获得信号量\n");

    sem_post(sem);

    sem_close(sem);

    return 0;
}
```

如果先运行 A：

```
A：
进程A获得信号量
```

此时 B：

```
进程B等待信号量...
```

5 秒以后：

```
A：
进程A释放信号量

B：
进程B获得信号量
```

这就是：

> **有名信号量实现不同进程之间的同步。**

---

## 三十八、三种机制放在一起

现在可以把本节三个知识点联系起来：

```
         进程间通信
              │
   ┌──────────┼──────────┐
   ↓          ↓          ↓
消息队列    共享内存    有名信号量
   │          │          │
   ↓          ↓          ↓
传递消息     共享数据    同步
```

非常重要的一点：

```
消息队列
    ↓
主要解决“传消息”

共享内存
    ↓
主要解决“共享大量数据”

有名信号量
    ↓
主要解决“同步”
```

---

## 三十九、共享内存 + 有名信号量

实际工程中经常把它们结合起来。

例如：

```
           进程A
             │
             │ 写数据
             ↓
      ┌──────────────┐
      │   共享内存    │
      └──────────────┘
             ↑
             │ 读数据
             │
           进程B

       有名信号量
            │
  ┌─────────┴─────────┐
  ↓                   ↓
控制A                控制B
```

完整过程：

```
A
 ↓
sem_wait()
 ↓
获得信号量
 ↓
写共享内存
 ↓
sem_post()
 ↓
通知B

B
 ↓
sem_wait()
 ↓
获得信号量
 ↓
读取共享内存
 ↓
sem_post()
```

## 四十、System V 信号量和 POSIX 有名信号量不要混淆

这里特别容易混。

Linux 中存在两套常见信号量接口。

### ① System V 信号量

主要函数：

```
semget()
semctl()
semop()
```

课程资料中也介绍了这一套接口：

```
semget()
 ↓
创建信号量数组

semctl()
 ↓
控制信号量

semop()
 ↓
申请/释放信号量
```

---

### ② POSIX 有名信号量

主要函数：

```
sem_open()
sem_wait()
sem_post()
sem_close()
sem_unlink()
```

通过：

```
名字
```

让不同进程访问同一个信号量。

---

## 四十一、System V 信号量

如果老师代码使用：

```
semget()
```

那么学习的是：

> **System V 信号量**

例如：

```
int semid;

semid = semget(
    key,
    1,
    IPC_CREAT | 0666
);
```

课程资料说明 `semget()` 用于创建信号量数组，`nsems` 表示信号量个数。

---

## 四十二、semctl()

```
semctl()
```

用于控制信号量。

例如设置初值：

```
semctl(
    semid,
    0,
    SETVAL,
    1
);
```

其中：

```
semid
 ↓
信号量数组 ID

0
 ↓
第0个信号量

SETVAL
 ↓
设置值

1
 ↓
初始值
```

课程资料列出的操作包括：

```
IPC_RMID
SETVAL
```

---

## 四十三、semop()

System V 信号量真正进行：

```
申请
释放
```

主要使用：

```
semop()
```

课程资料给出的原型：

```
int semop(
    int semid,
    struct sembuf *sops,
    size_t nsops
);
```

结构体：

```c
struct sembuf
{
    unsigned short sem_num;
    short sem_op;
    short sem_flg;
};
```

其中：

```
sem_num
 ↓
操作第几个信号量

sem_op
 ↓
进行什么操作

sem_flg
 ↓
操作标志
```

## 四十四、三种 IPC 机制对比

| 项目 | 消息队列 | 共享内存 | 有名信号量 |
| --- | --- | --- | --- |
| 核心作用 | 传递消息 | 共享数据 | 同步 |
| 数据量 | 中等 | 大量数据 | 不负责数据传输 |
| 数据形式 | 消息 | 内存区域 | 计数值 |
| 速度 | 较快 | 很快 | 主要用于同步 |
| 典型函数 | `msgsnd()` | `shmat()` | `sem_open()` |
| 接收/访问 | `msgrcv()` | 直接访问 | `sem_wait()` |
| 释放 | 自动/控制 | `shmdt()` | `sem_post()` |
| 删除 | `msgctl()` | `shmctl()` | `sem_unlink()` |

## 四十五、IPC对象的查看

Linux 提供：

```
ipcs
```

可以查看 IPC 对象。

分别：

```
ipcs -q
```

消息队列。

```
ipcs -m
```

共享内存。

```
ipcs -s
```

System V 信号量。

课程资料也明确给出了这些命令。

删除：

```
ipcrm -q 消息队列ID
ipcrm -m 共享内存ID
ipcrm -s 信号量ID
```

也可以根据 key 删除：

```
ipcrm -Q key
ipcrm -M key
ipcrm -S key
```
